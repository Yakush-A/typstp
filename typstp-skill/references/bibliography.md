# Список использованных источников: как вводить записи

Правила ввода источников для `typo-stp` 0.2.1 (СТП 01-2024, п. 2.8, ГОСТ 7.1-2003).
Применимо к **любому** документу: диплому, курсовой, лабораторной.
Все примеры проверены на реальном пакете: каждая запись из
`assets/sources.yml` собирается в строку, совпадающую с образцом СТП 2.8.6.

## 0. Главное

1. Источники — **только Hayagriva** (`sources.yml`). Не используйте `.bib`.
2. Список и его заголовок пакет строит сам (`#bibliography("sources.yml")`).
   Не пишите их вручную и не добавляйте `#show ".. –"`: пакет уже делает это.
3. Стиль сам ставит ` : `, ` / `, ` // `, ` – `, «[Электронный ресурс]»,
   «Режим доступа :», «В 2 т.», «Т. 1», «№», «С.», «с.», «[и др.]», «[Б. м.]».
   Не пишите эти знаки и слова в данных.
4. Перед созданием записи найдите подходящий образец в `assets/sources.yml`
   и копируйте его структуру. Не придумывайте поля и сокращения.
5. Всё, что стиль не умеет (раздел 5), делайте вручную в данных или
   сообщите пользователю об ограничении.
6. После сборки откройте список в PDF и сверьте записи с образцами СТП
   (раздел 7). Стиль не «экспериментальный», но у него есть известные
   пределы; они перечислены ниже.

## 1. Почему не `.bib`

Typst переводит BibLaTeX в Hayagriva с потерями. В `.bib` не работают:

- **4 и более авторов без заголовка записи** и **коллективный автор**: нет
  поля, которое даёт роль `collaborator`; всё из `author` становится
  заголовком записи.
- **«В 2 т.»**: поле `volumes` не передаётся.
- **Газета с датой** («5 марта»): остаётся только год.
- **«[Электронный ресурс]»** для `@software` и `@book`.

Если пользователь прислал `.bib`, перенесите записи в Hayagriva и скажите ему об этом.

## 2. Поля Hayagriva и что они дают

| Поле | Результат | Замечание |
| --- | --- | --- |
| `title` | основное заглавие | без « : », без «[Электронный ресурс]» |
| `genre` | сведения после « : » | `справ. пособие`, `монография`, `Datasheet`; вид издания со строчной |
| `author` | заголовок записи по **первому** автору + все (до 3) в ответственности | 1–3 автора |
| `affiliated` + `role: collaborator` | авторы **без** заголовка записи; при 4+ — «И. О. Фамилия [и др.]» | 4 и более авторов, коллективный автор, автор без инициалов |
| `editor` | «под ред. В. А. Шахнова» | фамилия в **родительном** падеже |
| `affiliated` + `role: translator` | «пер. А. Б. Петрова» | фамилия в родительном падеже |
| `volume-total` | «В 2 т.» после заглавия | |
| `volume` | «Т. 1» после выходных данных | для журнала «Т. 5, №3» |
| `edition` | число `2` → «2-е изд.»; строка выводится как есть | |
| `publisher.location` | место издания | сразу в нужной форме: `М.`, `СПб.`, `Минск` |
| `publisher.name` | издательство | нет места → «[Б. м.]»; нет издательства → «Город, год» |
| `date` | год; для газеты полная дата `2004-03-05` | |
| `page-total` | «288 с.» | только число |
| `note` | объём текстом: «1 компакт-диск (CD-R)» | используется, когда нет `page-total` |
| `page-range` | «С. 21–25» | `21-25` с дефисом |
| `issue` | «№12» | |
| `url` | «Режим доступа : …» | только абсолютный `http(s)://` |
| `parent` | источник для статьи: журнал, газета, сборник | см. раздел 4 |
| `type: web`, `type: repository` | автоматически «[Электронный ресурс]» | для остальных типов метку пишут в `title` |

## 3. Авторы: какое поле выбрать

| Ситуация | Что писать | Результат |
| --- | --- | --- |
| 1 автор | `author: "Гук, Михаил"` | `Гук, М. Заглавие / М. Гук.` |
| 2–3 автора | `author: [«Кузелин, …», «Кнышев, …», «Зотов, …»]` | заголовок по первому; в ответственности все |
| 4 и более авторов | `affiliated: [{role: collaborator, names: [...]}]` | `Заглавие / В. В. Клюев [и др.].` без заголовка |
| Коллективный автор | `collaborator`, одним полем: `"Intel Corporation"` | `Заглавие / Intel Corporation.` |
| Автор без инициалов (Аристотель) | `collaborator` | `Метафизика / Аристотель.` (через `author` теряется точка после имени) |
| Есть редактор, нет авторов | `editor: "Шахнова, В. А."` | `Заглавие / под ред. В. А. Шахнова.` |
| Переводчик | `affiliated` с `role: translator` | `/ Б. Керниган ; пер. А. Б. Петрова.` |

Правила ввода имён:
- формат `"Фамилия, Имя Отчество"` или `"Фамилия, И. О."`, стиль сам сделает
  «Фамилия, И. О.» и «И. О. Фамилия»;
- редактор и переводчик: фамилия в родительном падеже, стиль не склоняет;
- при 4+ авторах первым ставьте того, кто должен остаться в записи.

## 4. Образцы по типам источников

Полные записи — в `assets/sources.yml`. Здесь основные соглашения.

**Книга, 1–3 автора**

```yaml
kuz:
  type: book
  title: Современные семейства ПЛИС фирмы Xilinx
  genre: справ. пособие
  author: ["Кузелин, Михаил Олегович", "Кнышев, Дмитрий Александрович", "Зотов, Валерий Юрьевич"]
  publisher: {name: Горячая линия – Телеком, location: М.}
  date: 2004
  page-total: 440
```

**Книга, 4 и более авторов; коллективный автор; многотомник**

```yaml
klu:
  type: book
  title: Технические средства диагностирования
  genre: справочник
  affiliated:
    - role: collaborator
      names: ["Клюев, В. В.", "Иванов, И. И.", "Петров, П. П.", "Сидоров, С. С."]
  publisher: {name: Машиностроение, location: М.}
  date: 1989
  page-total: 672
# многотомник: добавьте  volume-total: 2   (в целом) и  volume: 1  (один том)
```

**Статья в журнале** (том, номер, страницы)

```yaml
berski:
  type: article
  title: Набор ЭСЛ-микросхем для быстродействующего RISC-процессора
  author: "Берски, Д."
  date: 1989
  parent: {type: periodical, title: Электроника}
  issue: 12
  page-range: 21-25
```

**Статья в сборнике**: название сборника целиком, с подзаголовком и «В 2 ч.», пишется
в `parent.title`; редактор сборника — в `parent.editor` (родительный падеж).

```yaml
aksenov:
  type: article
  title: Методика формирования обучающих выборок для распознающей системы
  author: "Аксенов, О. Ю."
  date: 2004
  page-range: 215-222
  parent:
    type: proceedings
    title: "VI Всероссийская науч.-техн. конференция «Нейроинформатика-2004» : сб. науч. тр. В 2 ч."
    editor: "Мишулина, О. А."
    publisher: {name: МИФИ, location: М.}
```

**Газета**: `parent.type: newspaper`, полная дата `date: 2004-03-05`, `page-range: 3`.
В пакете 0.2.1 со штатным CSL месяц выходит в именительном падеже («5 март»);
в обновлённом CSL (с месяцами в родительном падеже) — «5 марта». Если в
проекте штатный CSL 0.2.1, для газет указывайте только год.

**Сайт**: `type: web`, `url: http://…` → «[Электронный ресурс]. – Режим доступа : …».

**Файл в сети** (datasheet): `type: web`, `genre: Datasheet`, коллективный автор через
`collaborator`, `url` абсолютный.

**Компакт-диск**: `type: repository`, `genre` — содержание, `publisher.location`,
`date`, объём в `note: 1 компакт-диск (CD-R)`.

**Электронная книга** (`type: book` с `url`): метку «[Электронный ресурс]»
автоматически не ставят, допишите в `title`: `Учебник по Typst [Электронный ресурс]`.

## 5. Чего стиль не умеет (делает LLM или сообщает пользователю)

| Ограничение | Что делать |
| --- | --- |
| Не склоняет фамилии редактора и переводчика | писать в родительном падеже |
| Не сокращает города | писать `М.`, `СПб.`; **Минск полностью** (примечание 5 к 2.8.6) |
| Не подставляет «[Б. г.]» | при отсутствии года писать вручную или уточнить у пользователя |
| Автор без инициалов через `author` | использовать `collaborator` |
| Двойные точки на стыке областей («В 2 т.. – М.», «2-е изд.. –») | пакет склеивает их сам; просто проверить результат |
| Диссертации, стандарты, патенты, законы, архивные документы | образцов нет; не выдумывать, сообщить пользователю |
| Источник без ссылки в тексте в список **не попадёт** | в СТП 2.8.4 допускаются учебные материалы без ссылок в конце списка; пакет такого режима не поддерживает (не проверено), сообщить пользователю |
| `url` только абсолютный | для локального файла нужен полный адрес |

## 6. Ссылки в тексте и порядок

- Ссылка: `@key` или `#cite(<key>)`; оба дают `[N]`. Нумерация — по порядку
  **первого упоминания** в тексте, как требует п. 2.8.3.
- Точка после ссылки в конце предложения ставится после скобки: `...средств @guk.`
- Не пишите номера `[N]` вручную.
- Ссылка не должна переноситься на новую строку отдельно от предыдущего слова
  (п. 2.8.2). Пакет это не контролирует. Ставьте неразрывный пробел `~`
  перед каждой ссылкой: `...программных средств~@guk.` (проверено: в PDF
  между словом и `[1]` стоит неразрывный пробел).
- Wikipedia и другие вики запрещены (п. 1.2.16); не создавайте такие записи.
- Заимствованные формулы, таблицы и рисунки сопровождайте ссылкой на источник
  каждый раз (п. 2.4.1, 2.8.2).
- Не добавляйте в `sources.yml` источники, которых нет: не придумывайте авторов,
  годы, издательства, страницы. Если данных не хватает, спросите.

## 7. Проверка результата

После компиляции откройте PDF с `СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ` и проверьте:

1. Заголовок записи есть **только** у 1–3 авторов; у 4+ и коллективных его нет.
2. Знаки ` : `, ` / `, ` // `, ` – ` отделены пробелами; нет `..`, `, ,`, пустых мест.
3. «В 2 т.» перед «/», «Т. 1» после выходных данных; «№12», «С. 21–25».
4. Электронные ресурсы: «[Электронный ресурс]» сразу после основного заглавия
   (до « : » подзаголовка) и «Режим доступа : …» в конце.
5. «Минск» полностью, вид издания со строчной, инициалы через пробел.
6. Номера идут подряд в порядке первых ссылок.
7. Нет повторов вида «Заглавие : Заглавие»: так выглядит ошибка, когда `genre` дублирует `title`.
